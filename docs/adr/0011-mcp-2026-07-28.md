# ADR-0011: Align the MCP server with the 2026-07-28 specification and confirm irreversible actions

**Status:** Accepted

## Context
The Model Context Protocol (MCP) lets agents call tools on servers. Its 2026-07-28 specification
removed sessions: each request carries its own protocol version and client details. It also added
cache hints on tool lists, and a way for a server to answer "input required" so the client retries
the same call with the answers attached.

The server in `adjudication/mcp_server/server.py` already passed the person's identity with every
call. It did not check the protocol version, gave no cache guidance, and ran an irreversible tool
as soon as the checks passed. Nothing tested it.

## Decision
* A call with a protocol version other than 2026-07-28 is refused with
  `UNSUPPORTED_PROTOCOL_VERSION`.
* Tool lists carry `ttlMs` and `cacheScope: "private"`. The list is filtered for each caller, so a
  shared cache would show one officer's tools to another.
* An irreversible tool answers "input required" with a confirmation request addressed to the
  person the agent acts for. The call runs only when it is repeated with a confirmation from that
  person. Each confirmation works once.
* The registry's checks run before any confirmation is requested. Asking someone to confirm a call
  they could never make would reveal which tools exist.

## Consequences
* Seven tests in `tests/test_protocols.py` cover the version check, the private cache hint, the
  confirmation request, a confirmation from the wrong person, a replayed confirmation, a denied
  call and reads that need no confirmation.
* The shapes follow the specification's description. This is not a wire-level MCP server, and it
  does not use the `mcp` SDK.

## Open questions
* The confirmation is a field the client sends back, so a dishonest client can forge it. A real
  deployment must bind it to the officer, for example with a short-lived token from the identity
  provider that the server verifies. This needs a decision from whoever owns identity.
* Used confirmations are remembered in memory and are lost on restart.
